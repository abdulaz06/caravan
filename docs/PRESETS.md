# Presets — how a destination works, and how to add one

Everything that makes a trip *that* trip lives in a **preset**: a folder of
plain JSON and photos under `presets/<id>/`. The app itself has no idea about
any destination — the trip engine (`src/engine/`) reads the preset and the
organizers' live rules, and every screen asks the engine.

```
presets/
  preset.schema.json        ← generated JSON Schema (editor autocomplete)
  sri-lanka/
    preset.json             ← the destination: structure, catalog, map, costs, copy, theme
    photos.json             ← generated by the photo pipeline (credits, sizes, blur)
    photos.picks.json       ← which Wikimedia Commons files to use, per photo key
    photos.queries.json     ← (optional) search terms for finding candidates
    images/<dir>/*.webp     ← the optimised photos
```

At startup the server loads registered presets through `src/presets/registry.ts`
(fully validated outside production), and a page sends the browser only the
preset its trip uses — presets are never bundled into the client.

## The pieces of a preset

| Section | What it controls |
|---|---|
| `destination` | Name, timezone, the poster headline (`["Sri Lanka,", "your way."]`), tagline (+ `familyTagline`), season, hero photo, farewell line, stamp text, welcome-page showcase and teaser |
| `currency` | The local currency (shown first in the picker) and the default display currency. All prices are **USD**. |
| `dates` | The default date window organizers can move within `outer` |
| `structure` | Bases with nights (`default/min/max`), transfers between them, arrival/departure legs, the preview length, slot labels and "overpacked" limits |
| `areas` | The *pools* slots draw from (`colombo`, `enroute`, `galle`…), each with a home base and whether single picks can move between days |
| `regions` | Every place with coordinates and photo keys |
| `travel` | Known drive times, the distance estimate, fixed legs, scenic routes with stops, the vehicle ("van", "rental car"), self-drive or not |
| `map` | Projection, outline paths, the default frame, road chains, inland roads drawn as driven, label placement, a body of water to name |
| `stayIn` | "Stay in" copy for the daytime, the evening and (optionally) a transfer day ("Straight to Galle") |
| `specialDates` | Dates that take over a slot (New Year's Eve), with their own matchup per pool |
| `categories` | Labels and emoji for the catalog filters |
| `activities` | Options (A-vs-B matchups), Quick extras and family-friendly stand-ins |
| `pairs` | The A-vs-B matchups, kept separate so they're easy to re-pair |
| `costs` | Group size, vehicles, per-hour and per-day vehicle costs, accommodation per stay style × base |
| `preferences` | The choices on the preferences step (budget tiers in USD, stay styles, interests…) |
| `nightlifeTags`, `highlightLabels` | Extra nightlife tags; destination wording for trip highlights (temples → monasteries) |
| `theme` | Palette (semantic scales), fonts, illustration set, day colours, confetti |

### The day structure

The engine turns `structure.bases` into the trip, day by day
(`src/engine/structure.ts`):

```
Day 1                     arrival at the first base
…                         ordinary days at that base
first day at each next    a transfer day: the road from the previous base,
base                      daytime from the transfer's own pool if it has one
…                         ordinary days there (reorderable by drag)
last day                  check out & fly home — no slots
```

- **Sri Lanka** — Colombo 1 + Galle 4: *arrival · road trip · Galle · Galle · Galle · fly home*. The road trip's daytime draws from `enroute` (stops along the coast road, placed by `routeKm`); its evening is already in Galle.
- **One base** — **Georgia**, Tbilisi 8 nights: *arrival · seven Tbilisi days · fly home*, with self-drive rental cars (`travel.selfDrive`, `costs.dailyUsd`) and big day trips out to Gudauri, Kazbegi, Kakheti and the canyons of the west.
- Organizers can change the nights per base live; saved plans move over (each base's days map to that base's days, in order) after an impact preview.

### Activities

```jsonc
{
  "id": "galle-fort",                 // stable — saved in people's plans
  "kind": "option",                   // option | extra | family
  "slots": ["day"],                   // options: exactly one slot
  "areas": ["galle"],                 // which pools offer it
  "title": "Galle Fort: ramparts, boutiques & cafés",
  "region": "galle",
  "categories": ["culture", "food"],
  "tagline": "…", "loved": "…", "description": "…", "highlights": ["…"],
  "duration": "~4 hrs", "hours": 4,
  "estCostUsd": [5, 25],              // per person, USD
  "vibe": 0,                          // -2 nature … +2 nightlife
  "tags": ["walking tour", "history", "sunset"],
  "photo": "region-galle",            // optional: photo key (defaults to the id)
  "sources": [{ "label": "…", "url": "https://…" }]
}
```

Optional powers: `availableDays` (0 = Sun … 6 = Sat, e.g. `[5]` = Fridays
only), `rules` (a scorecard), `course` (pub-golf holes), `routeKm` (a stop on
a transfer route), `variants` + `onlyBaseDays` + `vehicleRoundTripUsd` + `bring`
(a big day trip with two ways to do it), `onlyWith` (an extra that needs another
pick in the same slot), `icon` (a custom illustration).

### Family-friendly mode

Every nightlife activity (category `party`, or a tag like `bar`, `club`,
`casino`, or one of `nightlifeTags`) needs a `familySwap`: a wholesome
stand-in in the same slot and pool — an existing option or a `kind: "family"`
activity. Copy elsewhere that mentions drinks gets `familyText`. The banned
words live in one place, `src/engine/family-banned-words.json`; the validator
fails a preset if family mode could show any of them.

### Theme

```jsonc
"theme": {
  "palette": {
    "primary":   { "950": "#04242c", …, "100": "#d6efeb" },  // main hue (sea/sky)
    "secondary": { … },  // nature
    "accent":    { … },  // warm call-to-action
    "highlight": { … },  // gold
    "pop":       { … },  // nightlife
    "night":     { … },  // evening slots
    "surface":   { … },  // page background
    "paper": "#fffbf4",
    "ink": { "1": "#1d1914", "2": "#4a4239", "3": "#73685a" }
  },
  "fonts": { "display": "fraunces", "body": "instrument" },
  "illustrations": "tropical",       // tropical | alpine
  "dayColors": ["#1a8e9c", …],
  "confetti": ["#f2a33a", …]
}
```

Components only use semantic classes (`bg-primary-800`, `text-highlight-400`);
a trip page puts its preset's palette in force (`src/lib/theme.ts`), so the
same screens look tropical in Sri Lanka and wintry in Georgia.

## How to add a destination

1. **Copy a preset.** `cp -r presets/sri-lanka presets/<id>` and set `"id": "<id>"`. Keep `"$schema": "../preset.schema.json"` for autocomplete.
2. **Shape the trip.** Edit `structure.bases` (one or more), `transfers` between consecutive bases, `areas` (one per base, plus a route pool if a transfer has stops), and the arrival/departure `legs`.
3. **Places & travel.** List every place in `regions` with real coordinates. Add drive times you know to `travel.known`; everything else is estimated from distance with `travel.estimate` (tune `kmh` to the roads).
4. **The map.** `python scripts/make-map-outline.py ne_10m_admin_0_countries.geojson "<Country>" --scale 80` turns Natural Earth's public-domain country polygons into `projection`, `width`, `height`, a simplified `outline` and a detailed `detail` path. Away from the equator it sets `projection.xScale` (≈ cos latitude) so the country isn't stretched sideways. For a country with land borders, add `--surround "Neighbour,Neighbour"`: the `surroundings` path is drawn as quiet land, so only real sea reads as water (Georgia uses Russia, Turkey, Armenia and Azerbaijan). Set `map.focus` to the area the trip happens in; add `chains` for roads that link towns in order and `roads` for winding routes.
5. **The catalog.** Research real, currently operating places (two recent sources each, real traveller reviews over listicles), then write `activities` and `pairs` — at least one daytime and one evening matchup per pool. Give every nightlife item a `familySwap`.
6. **Photos.** List Wikimedia Commons files per key in `photos.picks.json` (`node scripts/image-candidates.mjs <id> <outDir>` builds contact sheets from `photos.queries.json`), then run `npm run photos -- <id>`. Check the licences allow reuse; credits are shown in the app.
7. **Theme.** Pick a palette that suits the place, fonts and an illustration set.
8. **Register it.** Import `preset.json` and `photos.json` in `src/presets/registry.ts`.
9. **Validate.** `npm run preset:validate -- <id>` checks the schema, every cross-reference, photos on disk and family mode's banned words; fix until it's green. `npm test` runs the engine tests.

That's it — no component changes. If a destination needs something the format
can't express yet, extend `src/engine/preset-schema.ts` (and the validator),
keep the new field optional, and teach the engine to read it.
